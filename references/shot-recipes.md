# 四类镜头的做法

分镜表里每个镜头先归类，再按对应配方做。四类的产线和坑完全不同。

---

## A · 空镜（建立镜头）

**特征**：没有对白主体，功能是建立空间与气氛。

**产线**：静帧 → 图生视频

### 要领

1. 画面里**真的没有人**，除非剧本要求
2. 让人动起来的元素至少三处：蒸汽/烟/雨、光、人群、机械运转、水面
3. 镜头运动要写死（"极缓前推 5%""固定机位轻微手持浮动"），不要留给模型
4. 时长够用就好，多出来的部分留给剪辑余量

### 提示词要点

- 写明"no person appears anywhere in frame and nobody speaks"（如果确实是空景）
- 写明各元素的运动方式，而不是"让画面动起来"
- 结尾不要写"然后镜头停下"，写"保持到最后一帧"

### 常见失败

- 模型自己加了个人
- 镜头自己推得太快，5 秒里从全景推到中景，取前 2 秒还好，取全长就太急
- 蒸汽/烟的运动幅度过大，像在喷气

---

## B · 口播镜头（要对口型）

**特征**：有人说话，需要对口型。

**产线**：近景静帧 → 对口型模型（图 + 音频）

### 参考图规格（决定成败）

| 项 | 要求 |
|---|---|
| 朝向 | 正脸，或不超过 15° 侧转 |
| 嘴部 | **完全无遮挡**，无手、无杯、无麦克风挡在下巴前 |
| 面部占比 | 约占画幅宽 35% |
| 眼睛 | **张开且可见**，不要眯眼笑 |
| 表情 | 自然，嘴微张或半张，像正在说话 |
| 光线 | 嘴部要有光，不能陷在阴影里 |
| 画面 | 16:9，人略偏离正中 |

### 音频准备（决定口型准不准）

**这是最容易忽略、影响最大的一步。**

对口型模型是按音频里的语音来驱动嘴形的。如果音频里有大段静音，模型没有目标可对，会把口型动作随便铺满整段。

实测过一个真实案例：一条 2.57 秒的配音，语音只占 0.50–1.26 秒（29%），模型给出的结果是"没声音的时候嘴张得最大，说话的时候嘴是抿着的"。

**处理方法**：

1. 用静音检测量出语音的真实起止
2. 裁掉前后静音，**但尾部要留 0.5–0.7 秒静音**——这是给模型"闭嘴"的时间
3. 中间语音段占音频总长的 40–60% 最理想

```bash
# 量出语音边界
ffmpeg -i line.mp3 -af silencedetect=n=-40dB:d=0.05 -f null -
```

### 提示词要点

- 明确"音频静音后立刻闭嘴，双唇合拢，保持到最后一帧"
- **用否定清单压制夸张表情**：`NO pouting, NO puckered lips, NO kiss face, NO duck lips, NO exaggerated smile`
  - 只写 "closed-mouth smile" 会被理解成"抿嘴笑"，也就是嘟嘴
- 写"completely static camera"，对口型模型一动就破

### 常见失败

- 画面烧进假字幕（部分接口面对语音时会自动加）→ 只能裁掉底部条带，见 `qc-checklist.md`
- 结尾嘟嘴 → 加否定清单 + 留尾部静音
- 口型错位 → 检查音频静音占比，不要重复跑同一个音频

## C · 转场镜头

**特征**：两个场景之间，靠画面元素完成过渡。

**产线**：首尾帧 + 图生视频，或纯代码

### 类型与做法

| 类型 | 做法 | 提示词关键 |
|---|---|---|
| 穿门 / 穿缝 | 主体撞进一道光缝，光爆吃掉半个画面 | 明确撞进去**之后往哪个方向继续** |
| 形态匹配 | 蒸汽→热气、反光→街景 | 前后两镜的过渡元素要有相同的形状和运动方向 |
| 白闪 / 黑切 | 纯代码做 2–3 帧 | 不需要生成 |
| 声音先行 | 下一段的声音提前 0.2 秒进 | 不需要生成，剪辑层解决 |

### 方向必须自洽（重要）

一个真实事故：主体**从左往右**飞，撞进画面**右侧**的光缝，但尾帧却被写成"从左侧飞出"。

这在物理上说不通，剪起来会让观众觉得主体凭空回到了起点。

**尾帧必须写清"撞进去之后继续往哪个方向"**：

- 继续前进 → 主体在光缝的另一侧，往原方向出画
- 反弹 / 停住 → 需要交代是什么让它停下的

写转场镜头的锚时，先在心里放一遍这个物体的运动轨迹，确认它是连续的。

## D · 文字 / 排版镜头

**特征**：画面主体是文字、标板、Logo、数据。

**产线**：**代码渲染，不用生成模型。**

### 为什么

- 生成模型对字形不可靠，中文尤其明显（笔画结构会坏，放大即穿）
- 同一条文字在不同镜头里必须字形一致，生成模型做不到
- 字重、字距、行距、对齐需要精确控制，这是排版需求，不是渲染需求

### 工具

- **HyperFrames**（HTML → 视频，逐帧确定）
- Remotion
- 纯 ffmpeg + drawtext（简单字幕）

### 版式的最小规格

一条可执行的文字层规格至少要有：

```
字体族 / 字重 / 字号 / 字距 / 颜色（十六进制）
对齐方式 / 锚点位置（几分点）/ 距边距（画宽百分比）
入场：时长 + 位移量 + easing
停留：时长
出场：时长
```

例：
```
英文 64px Inter Tight Medium，字距 −1%，色 #E8E6E3
中文 27px 思源黑体 Light，与英文基线对齐
右对齐，锚在画面右三分点、垂直居中偏下，距右边距 ≥12% 画宽
入场：0.5s 淡入 + 4px 上移，ease-out
```

### 一个纪律

**标板类元素不要每段重写一遍。** 做成一个组件，用变量暴露文案，全片复用。改一次全片生效，字形也自动统一。

---

## 四类之外 · 混合镜头

有些镜头是"生成画面 + 代码叠层"：

- 生成模型出底片（光影、材质、运动）
- 代码叠标板、数据、字幕

**分界线**：镜头里一切需要"精确、可复读、有字形"的东西，都在代码层；一切需要"真实感、材质、有机运动"的，都在生成层。

典型例子：16 个指示灯逐个点亮。生成模型只会给你一段"整体慢慢变亮"，而且可能乱闪。正确做法是让它出"整体渐亮"的底片，**16 次点亮的节奏全部由代码按 0.15 秒间隔控制**——因为"逐个"这件事本身就是这个镜头的语义，不能被随机化。
